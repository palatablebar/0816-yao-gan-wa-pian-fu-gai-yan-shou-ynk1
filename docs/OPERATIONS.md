# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核，同一来源不覆盖已签结论。
4. 判断交付口径：
   - 全分辨率瓦片齐备（`balance.delivery.choice=SIGN_FULL`）时直接正式签发。
   - 截止日只有低分辨率预览补齐（`choice=DELIVER_PROXY`）时先交临时代理，
     正式签发待全分辨率瓦片齐备后另跑一批。
   - 覆盖仍不足或存在隔离、待处理分组（`choice=HOLD`）时只能暂缓。
5. 对账无差异且无坏行、交付口径为 `SIGN_FULL` 时才可正式签发；`DELIVER_PROXY` 时只能代理交付；
   其余填写暂缓意见。`blocks` 列出每一处挡住签发的对账项。
6. 导出复核证据并保存于交接记录；代理交付的证据同样保留，正式签发不会覆盖旧版。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
