# 字段与业务定义

输入编码 UTF-8，允许 BOM。首行必须匹配样例列顺序。记录键和业务组保留原始字符串。`kind` 允许 region, tile, preview。说明列 `note` 可以跨行，限制 200 字。

业务字段按 `x0`、`y0`、`x1`、`y1`、`min_cells` 排列。数字接受非负整数、全角数字和完整千分位。空串、短横线、N/A、NULL 与未知为缺值。无关字段用 0 占位。

瓦片为整数网格上的左闭右开矩形。扫过相邻 X 边界，按 Y 区间并集求有效像元。输入重叠多计量与真实缺口独立提供。

## 分辨率层级

- `tile`：全分辨率正式瓦片，用于正式验收。
- `preview`：低分辨率预览瓦片，只用于临时代理，不计入正式覆盖。

`prepare` 先把每块瓦片裁到作业区。越出作业区的面积只记为排除量 `excluded.outside_cells`，不进入覆盖账。

`calculate` 分别归并两层，同一像元被多块瓦片覆盖只计一次：

- `formal`（正式覆盖）：仅 `tile` 的并集。
- `proxy`（代理覆盖）：`tile` 与 `preview` 合并的并集；`proxy_gain_cells` 为预览带来的增量。

`policy` 依据全分辨率覆盖给出结论：

| 结论 | 条件 | 交付建议 |
|---|---|---|
| `READY` | 正式覆盖达到 `min_cells` | `SIGN_FULL` 正式签发 |
| `PROVISIONAL` | 正式不足、代理覆盖达到 `min_cells` | `DELIVER_PROXY` 先交临时代理 |
| `COVERAGE_GAP` | 代理覆盖仍不足 | `HOLD` 暂不能交付 |

## 对账

`balance` 同时给出两份逐项账，任何一项对不上都挡住签发：

- 行账 `rows`：来源 = 采信 + 隔离 + 忽略，采信 = 各分组记录数之和。
- 像元账 `pixels`：每个有计算值的分组逐组核对 `覆盖 + 缺口 = 作业区`、
  `代理覆盖 = 正式覆盖 + 代理增量`、`毛面积 = 覆盖 + 重叠多计`、
  `原始毛面积 = 裁剪后毛面积 + 越界面积`。

`releasable`（可正式签发）要求行账与像元账都对平、无隔离行、所有分组 `READY`。
`proxy_releasable`（可代理交付）要求两份账对平、无隔离行、所有分组为 `READY` 或
`PROVISIONAL`，且至少存在一个 `PROVISIONAL`。

`incoming.csv` 包含四个业务组，第二组提供不同边界，第三组触发业务拒收，第四组需要核对。另含重复表头、冲突记录、重复回放与错误列数。`ready.csv` 含可以签发的两个组。`deadline.csv` 含一个仅够代理的分组与一个全分辨率齐备的分组。
